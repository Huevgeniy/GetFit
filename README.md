# 🏋️ GetFitBot

Telegram Mini App для учёта тренировок, питания и сна: 1ПМ-калькулятор, отчёты за период, шаблоны тренировок с шарингом, ИИ-тренер и необязательные дополнительные разделы.

**Стек:** React 19 + Vite + Tailwind (клиент) · Express + TypeScript (сервер) · Postgres/Supabase · Groq + Gemini (ИИ) · Telegram Bot API.

## Быстрый старт

```bash
npm install
npm run dev      # http://localhost:3000
```

В дев-режиме вход без Telegram разрешён: создаётся локальная сессия `dev:<id>`.
Данные пишутся в `data/cloud_db.json`, пока не задан `DATABASE_URL`.

## Базовый и расширенный режимы

Новый пользователь попадает в **базовый режим**. Внизу остаются четыре вкладки:

- **Тренировки** — планы, свободная тренировка, конструктор и личные шаблоны;
- **Питание** — еда, КБЖУ, вода и сон;
- **Прогресс** — графики 1ПМ, тоннажа и кнопка **«Отчёт за период»**;
- **Профиль** — параметры, InBody, рекорды, напоминания, экспорт и настройки режима.

Отчёты больше не отдельная вкладка и не сообщения бота по расписанию: отчёт открывается
кнопкой внутри «Прогресса». Периоды — 7, 30, 90 дней или всё время. В сводке: тренировки,
тоннаж, подходы, средний RPE, время в зале, сон, калории, шаги, вес и динамика к предыдущему
периоду. Шаги вносятся в профиле по дням и синхронизируются между устройствами вместе с дневником.

В **Профиле → Режим приложения** включается расширенный режим. После этого появляются
тумблеры, каждый из которых добавляет один раздел:

| Тумблер | Что появляется |
|---|---|
| Марафоны целей | Вкладка «Марафоны» внутри «Тренировок» |
| Зарубы с друзьями | Вкладка «Зарубы» и раздел «Друзья & Зарубы» в профиле |
| Дисциплина и штрафы | Вкладка «Дисциплина» и раздел «Награды» |
| Спортивные разряды | Вкладка «Разряды» с нормативами |
| Лаборатория N=1 | Вкладка для личных экспериментов |
| Циклы и периодизация | Вкладка с блоками гипертрофии, силы и делоада |

Все дополнительные разделы по умолчанию выключены — даже в расширенном режиме. Если включить
больше одного, нижняя панель не разрастается: остаются четыре базовые вкладки и «Ещё» с
дополнительными разделами. Обучение при первом запуске проходит по четырём базовым вкладкам,
объясняет кнопку отчёта и каждый тумблер; его можно запустить заново из настроек.

## Шаблоны и шаринг

- **Мои шаблоны** — библиотека, запуск в один клик, редактирование, дублирование и удаление.
- **Поделиться другу** — создаёт ссылку `https://t.me/<bot>?start=tpl_<код>`. Бот отвечает
  кнопкой, которая открывает Mini App и сразу добавляет шаблон в «Мои шаблоны».
- **Общие шаблоны** — публичная библиотека. Владелец может опубликовать шаблон, снять
  с публикации или удалить его; у чужих шаблонов видно автора и число копий.
- **Забрать по коду или ссылке** — вставь `tpl_XXXXXXXX` или полную ссылку вручную.

Шаблоны хранятся на сервере в таблице `shared_templates` (Postgres) или в JSON-файле при
локальном запуске.

## Экспорт дневника

**Профиль → Таблица в чат (Google Sheets)** отправляет CSV-файл
`getfit-diary-YYYY-MM-DD.csv` в чат с ботом. Файл открывается в Google Sheets, Excel и
Numbers. Прямая запись в Google Sheets требует OAuth, поэтому выбран безопасный экспорт
файла через Telegram.

## Переменные окружения

Скопируй `.env.example` в `.env`:

| Переменная | Зачем |
|---|---|
| `TELEGRAM_BOT_TOKEN` | бот, проверка initData, уведомления |
| `GROQ_API_KEY` | основной ИИ-провайдер (бесплатный) |
| `GEMINI_API_KEY` | резервный ИИ-провайдер (недоступен из РФ) |
| `APP_URL` | публичный адрес Mini App (для webhook и ссылок-приглашений) |
| `DATABASE_URL` | Postgres/Supabase. Без него — локальный JSON-файл |
| `SESSION_SECRET` | подпись сессий (если пусто — выводится из токена бота) |
| `TELEGRAM_WEBHOOK_SECRET` | проверка, что webhook зовёт именно Telegram |
| `GROQ_MODEL` / `GEMINI_MODEL` | переопределение модели (по умолчанию `qwen/qwen3.8-27b`, `gemini-flash-latest`) |

## Команды

```bash
npm run dev          # сервер разработки (Vite middleware + бот на polling)
npm run build        # сборка клиента и сервера в dist/
npm start            # прод-запуск из dist/
npm run lint         # проверка типов (tsc --noEmit)
npm run doctor       # проверка окружения перед деплоем: токен, ключи, APP_URL, база
npm run test:client  # логика входа и синхронизации — 13 проверок, без сервера
npm run test:pg      # Postgres-ветка хранилища на in-memory Postgres — 30 проверок
npm run test:css     # сборка Tailwind v4 из src/index.css — 15 проверок
npm run test:render  # рендер приложения и всех экранов, режимы и отчёт — 42 проверки
npm run test:dom     # DOM (jsdom): вкладки, «Ещё», отчёт, тумблеры, шаблоны — 61 проверка
npm run test:notify  # логика напоминаний — 17 проверок
npm run test:inbody   # разбор чисел InBody без пересчёта процента жира — 19 проверок
npm run test:smoke   # API целиком, включая шаринг шаблонов — 58 проверок, нужен сервер
npm run test:deploy  # проверка развёрнутого сервиса: webhook, меню, health, закрытость API
npm run test:live    # сквозной прогон по живому серверу и реальной базе (с уборкой данных)
npm run test:live-ui # клиентский код в DOM против живого сервера и Supabase
npm run test:ai      # какой ИИ реально отвечает на развёрнутом сервере
```

**Развёрнутое приложение:** https://getfit-kqhi.onrender.com · бот: [@get_fitbot](https://t.me/get_fitbot)

## Архитектура

```
src/                 клиент
  lib/api.ts         сессия по Telegram initData, облачная синхронизация, CSV и шаблоны
  lib/features.ts    режимы приложения и флаги дополнительных разделов
  lib/telegram.ts    обёртка WebApp SDK: тема, safe-area, haptics, кнопка «Назад», шаринг
  components/        экраны и модалки; тяжёлые экраны и модалки загружаются лениво
server.ts            HTTP API, ИИ-слой, CSV-экспорт, шаринг шаблонов, бот
server/auth.ts       проверка initData (HMAC + срок жизни), сессионные токены
server/inbody.ts     явный разбор чисел InBody без домысливания процентов
server/storage.ts    Postgres с миграциями, JSON-файл как fallback, общие шаблоны
scripts/             сквозные тесты
```

**Безопасность.** Все `/api/*`, кроме `health`, `auth` и `webhook`, требуют сессию.
Идентификатор пользователя берётся только из подписанного токена — подставить чужой нельзя.
`initData` проверяется по HMAC-SHA256 с контролем `auth_date`, сравнение — timing-safe.
На ИИ-эндпоинты стоит лимит 40 запросов / 5 минут на пользователя.
